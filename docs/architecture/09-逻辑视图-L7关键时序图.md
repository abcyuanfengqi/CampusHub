## 1. 时序图一：活动报名流程（跨模块 + 异步消息 + 异常分支）

![L7-活动报名时序图](images/L7-活动报名时序图.png)

**Mermaid 源码（可复现）**：
```mermaid
sequenceDiagram
    autonumber
    participant 学生
    participant 前端页面
    participant ActivityController
    participant ActivityService
    participant DB as DB/Redis
    participant MQ as RabbitMQ/通知

    学生->>前端页面: 点击报名活动
    前端页面->>ActivityController: POST /activity/{id}/register (JWT)
    ActivityController->>ActivityService: register(activityId, userId)
    ActivityService->>DB: SELECT activity 校验状态/名额
    ActivityService->>DB: Redis INCR 原子扣减名额
    ActivityService->>DB: UPDATE 乐观锁回写(version)
    ActivityService->>MQ: 发布 REGISTRATION_EVENT
    MQ-->>DB: 消费事件→写notification
    ActivityController-->>前端页面: 返回 code:200 报名成功
    前端页面-->>学生: 显示"报名成功"+站内消息

    Note over ActivityService,DB: 异常分支：<br/>1. 状态≠REGISTERING → 拒绝<br/>2. Redis计数达上限 → 500"名额已满"<br/>3. 唯一键冲突 → 500"重复报名"
```

**流程说明**：
1. 前端带 JWT 调用报名接口（第2步），Controller 只做参数校验
2. ActivityService 校验活动状态（必须 REGISTERING）与名额（第4步）
3. **Redis INCR 原子扣减**（第5步）：利用 Redis 单线程特性防并发超卖，扣到上限即拒绝
4. **乐观锁回写**（第6步）：`UPDATE ... WHERE version=?` 失败则重试（结合 ADR-004）
5. **异步通知**（第7-8步）：报名事务提交后发布 REGISTRATION_EVENT 到 RabbitMQ，通知消费者异步写站内消息——**报名接口不阻塞等通知，解耦且提升吞吐**
6. 前端轮询/即时返回结果（第9-10步）

## 2. 时序图二：社团创建与审批流程（状态机 C2）

```mermaid
sequenceDiagram
    autonumber
    participant 学生 as 学生(社长)
    participant 前端
    participant ClubController
    participant ClubService
    participant Admin
    participant MQ as RabbitMQ/通知

    学生->>前端: 提交社团申请
    前端->>ClubController: POST /api/club (JWT)
    ClubController->>ClubService: createClub(dto)
    ClubService->>ClubService: 校验名称唯一/分类合法
    ClubService-->>前端: 返回 id, status=PENDING
    前端-->>学生: "提交成功，待管理员审批"

    Admin->>ClubController: POST /api/club/{id}/approve
    ClubController->>ClubService: approve(clubId)
    ClubService->>ClubService: 状态 PENDING→APPROVED
    ClubService->>MQ: 发布 CLUB_APPROVED_EVENT
    MQ-->>ClubService: 消费者→写通知给社长
    ClubService-->>前端: code:200
    前端-->>Admin: 审批完成

    Note over ClubService: 异常分支：名称重复→拒绝；<br/>非PENDING状态→非法流转报错；<br/>REJECTED 需填写驳回理由
```

**说明**：演示**管理员审批流状态机**（PENDING→APPROVED/REJECTED），审核结果通过异步消息通知申请人——体现角色权限（C1）与异步通知。

## 3. 时序图三：用户登录认证流程（JWT + Redis 会话）

```mermaid
sequenceDiagram
    autonumber
    participant 学生
    participant 前端
    participant AuthController
    participant AuthService
    participant DB as MySQL
    participant Redis

    学生->>前端: 输入用户名密码
    前端->>AuthController: POST /api/auth/login
    AuthController->>AuthService: login(username, password)
    AuthService->>DB: SELECT user WHERE username=?
    alt 用户不存在或密码不匹配
        AuthService-->>前端: code:500 "用户名或密码错误"
        前端-->>学生: 提示错误
    else 校验通过
        AuthService->>Redis: 存会话缓存 user:{id} (TTL 2h)
        AuthService-->>前端: 返回 { token, userInfo }
        前端->>前端: 存 token 到 Pinia/LocalStorage
        前端-->>学生: 登录成功，进入首页
    end
    学生->>前端: 访问业务接口（带 token）
    前端->>AuthController: JWT 过滤器校验 token
    AuthController->>AuthService: 解析并校验 JWT + Redis 会话
    AuthService-->>前端: 通过，放行
```

**说明**：登录 = MD5 校验密码 + 签发 JWT（2小时）+ Redis 缓存会话状态；后续请求经 JWT 过滤器（Spring Security 放行 /auth/**，其余校验）——对应 ADR-005 认证授权设计。
