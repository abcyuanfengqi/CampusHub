# ADR-007：部署形态（Docker Compose 单机部署）

| 要素 | 内容 |
|------|------|
| **日期** | 2026-10-27 |
| **状态** | 已接受 |
| **涉及视图** | 物理视图 P1/P4、运行视图 R1、开发视图 V5 |
| **背景** | 项目要求"系统可运行、可演示、可部署"（演示与答辩 9 分、在线环境），需要一套可复现的部署方案；个人项目资源有限，需平衡"易演示"与"可扩展" |

## 备选方案

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| A. 纯本机进程部署 | JDK/MySQL/Redis/RabbitMQ 直接跑在本机 | 最快、便于开发调试 | 环境难复现、无法演示"部署能力" |
| B. Docker Compose 单机编排 | 5 个容器（nginx/backend/mysql/redis/rabbitmq）一条命令起 | 可复现、可迁移、演示效果好 | 需维护 Dockerfile/编排文件 |
| C. 云服务器 + 域名 | 公网部署 | 可公网访问、真实可用 | 有成本、需备案/公网资源 |

## 决策

采用 **方案 B 为主：Docker Compose 单机编排**（开发期继续用本机进程，部署/演示用 Compose）；方案 C 作为可选加分项（第13周如有条件部署到校园网/云）。

## 理由

1. 任务书要求"在线环境 + 可运行"：Compose 一键启动（`docker compose up -d`）是最低成本的可复现方案
2. 前期 Docker Desktop 在 WSL2 上启动失败（VHDX 创建错误），已卸载——Compose 方案保留 docker-compose.yml 作为交付物，实际演示可用本机进程（7-环境配置脚本/start-dev-env.bat 已备）
3. 命名卷持久化（mysql_data）保证数据不因容器重建丢失
4. 生产扩展路径清晰：同镜像多副本 + Nginx 负载均衡（P1 图标注）

## 影响

- 交付 `docker-compose.yml`（07-环境配置脚本目录已有），含 mysql/redis/rabbitmq/backend/nginx 五服务
- 后端 Dockerfile：`maven:3.9-eclipse-temurin-17` 构建 + `eclipse-temurin:17-jre` 运行
- 前端构建产物由 nginx 容器托管（静态 SPA）
- 验证方式见下方

## 验证方式

1. 全新环境执行 `docker compose up -d` → 5 个容器健康（`docker ps`）
2. 访问 `http://localhost` 打开前端、`/api` 打通后端
3. 重启容器后数据仍在（命名卷验证）
4. 演示视频（第15周）用 Compose 启动录制备份
