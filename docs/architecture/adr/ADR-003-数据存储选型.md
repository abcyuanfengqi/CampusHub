# ADR-003：数据存储选型

- 日期：2026-10-27
- 状态：已接受
- 涉及视图：数据 / 运行 / 物理

## 背景

CampusHub 需要持久化 19 张业务表（用户/社团/竞赛/活动/二手/失物/消息/统计等），涉及事务（活动报名名额递减、二手交易状态流转）、复杂查询（多条件筛选、统计聚合）、以及每日运营统计数据。需要选择关系型数据库及配套方案。

约束条件：
- 单机可部署（本机开发 + 第13周 Docker 部署）
- 必须支持 ACID 事务（报名扣减名额必须原子）
- 个人开发，要求运维简单、社区成熟
- 需满足数据视图 D1（ER图 ≥10实体）与 D2（数据字典 ≥10表）交付要求

## 备选方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. MySQL 8.0（InnoDB） | 事务完备（ACID）、SQL标准、utf8mb4中文友好、运维成熟、主从/集群生态完善；与 MyBatis-Plus 配合最佳 | 单表千万级后需分库分表（本项目规模远达不到）；JSON支持弱于PostgreSQL |
| B. PostgreSQL 16 | 功能更强（JSONB/CTE/数组）、开源许可宽松 | 国内教程/AI语料相对少；MyBatis-Plus兼容度略低；本人不熟悉 |
| C. SQLite | 零部署、嵌入式 | 不支持并发写、无网络访问能力，无法支撑 Web 多连接场景 |
| D. MongoDB（文档型） | 无模式、易扩展 | 无强事务（多文档事务有限）、关联查询弱；本项目实体关系强（外键多），不匹配 |
| E. 云数据库（RDS等） | 免运维、自动备份 | 需要云账号与付费；本项目单机 Docker 足够，成本不必要 |

## 决策

**选择 A：MySQL 8.0（InnoDB 引擎，utf8mb4），本地端口 3306。**

配套选型：
- 连接池：HikariCP（Spring Boot 默认）
- ORM：MyBatis-Plus 3.5.5（配合 ADR-001）
- 字符集：utf8mb4（支持 emoji 与中文）
- 引擎：InnoDB（事务 + 行级锁 + 外键支持）
- 数据名：campus_hub，19 张表（见 D1/D2）

## 理由

1. **事务与一致性**：报名递减（`current_participants` 乐观锁更新）、二手交易状态流转都需要 ACID；MySQL InnoDB 是标准选择，MyBatis-Plus 乐观锁注解（`@Version`）开箱即用。
2. **生态与运维**：MySQL 是课程/就业最主流数据库，Navicat/DBeaver 工具链成熟，Docker 镜像小、单机内存占用可控（本项目数据量 < 1GB）。
3. **中文场景**：utf8mb4 完整支持中文与 emoji（社团简介、商品描述含表情符号场景）。
4. **放弃的代价**：放弃 PostgreSQL 意味着损失 JSONB/更高级查询——本项目结构化强、JSON 仅用于图片列表（TEXT 存 JSON 数组足够），代价可忽略。放弃 MongoDB 因其事务弱、不匹配强关系模型。
5. **性能**：千级用户、峰值 QPS 100 场景，单表索引（唯一键已建 uk_*）+ 连接池配置即可满足 ≤100ms 单表查询（见非功能需求 5.1）。

## 影响

- **数据视图**：D1 ER 图（19 实体）、D2 数据字典（逐字段说明）均基于此表结构
- **运行视图**：MySQL 单实例，端口 3306，每日备份（mysqldump cron）
- **物理视图**：Docker 容器 mysql:8.0，数据卷持久化
- **质量属性**：可用性（每日备份 + 重启自恢复）、性能（索引 + 连接池）
- **后续事项**：第10-12周按模块编写 MyBatis-Plus Mapper/Service；第13周 Docker 化

## 验证方式

1. `SHOW TABLES` 显示 19 张表（已验证 ✅）
2. 登录事务写入 sys_user 成功（已验证 ✅）
3. 报名扣减名额在高并发下无超卖（第11周 C2 状态机验收，用乐观锁验证）
4. 单表查询 ≤100ms（第12周压测）
5. 数据量增长超千万级或需要跨库事务时，重新评估分库分表或 PostgreSQL
