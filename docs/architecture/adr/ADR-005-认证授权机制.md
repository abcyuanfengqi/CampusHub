# ADR-005：认证授权机制

| 要素 | 内容 |
|------|------|
| **日期** | 2026-10-27 |
| **状态** | 已接受 |
| **涉及视图** | 逻辑视图 L3/L4/L6、运行视图 R1/R2 |
| **背景** | 系统有 3 类角色（学生/社团负责人/管理员），9 个业务模块都需要接口鉴权；要求满足 C1 复杂度（≥3 类角色权限控制），且登录态需可校验、可过期、无状态（便于未来横向扩展） |

## 备选方案

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| A. Session + Cookie（服务端会话） | Tomcat 内存或 DB 存会话 | 实现简单、可主动失效 | 有状态难扩展、集群需共享会话 |
| B. JWT 无状态 Token | 签名自校验，Redis 辅助 | 无状态可扩展、跨端通用 | 无法主动撤销（靠过期） |
| C. OAuth2 / 校园统一认证 | 对接外部 IdP | 用户免注册 | 依赖外部系统、开发复杂 |
| D. JWT + Spring Security + RBAC | 组合方案，角色-权限模型 | 安全可控、可扩展、满足多角色 | 需实现角色权限配置 |

## 决策

采用 **方案 D：JWT（HS384 签名，2 小时过期）+ Spring Security 过滤器链 + RBAC 角色权限模型**，Redis 保存会话辅助状态（`user:{id}` 存活期 2 小时），登录、注册接口放行，业务接口统一鉴权。

## 理由

1. 个人完成项目规模下，JWT 无状态方案部署最简单（无需会话共享），符合"可运行"目标
2. Spring Security + JwtUtils 过滤链可精确控制"哪些路径匿名/哪些需认证/哪些需 ADMIN 角色"（当前放行 `/auth/**`、`/system/**`、swagger 文档）
3. 3 类角色权限用注解 `@RequireRole(ADMIN)` 声明，满足 C1 复杂度且可测试
4. 已实现代码验证：`SecurityConfig` + `JwtUtils`（jjwt 0.12.6）+ 登录注册接口联调通过

## 影响

- 后端：新增 SecurityConfig、JwtUtils、AuthController；业务接口需带 `Authorization: Bearer` 头
- 前端：Axios 拦截器统一携带 Token；401 时跳转登录页（已实现 request.js）
- 测试账号：admin/123456（ADMIN）、student/123456（STUDENT），密码 MD5 存储

## 验证方式

1. 用测试账号调用 `/api/auth/login` 获取 Token → 带 Token 访问业务接口返回 200
2. 不带 Token / 错误 Token 访问业务接口 → 返回 401
3. 学生账号访问管理员接口 → 返回 403（无权限）
4. `mvn test` 单测覆盖登录、鉴权、越权场景（第12周累计 ≥10 个）
